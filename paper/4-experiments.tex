\section{Experiments} \label{sec:experiments}

We conduct a series of evaluations on the MMDA benchmark to demonstrate the effectiveness of \modora in processing semi-structured documents.

\subsection{Experimental Configuration}
\runin{Dataset and Metric} Our evaluation uses the MMDA dataset introduced in MoDora~\cite{xu2026modora}, which contains 1,065 QA pairs in 537 documents with different layouts. We employ AIC-Acc (\%) as the primary evaluation metric, using an LLM-based judge to verify correctness of the responses while allowing for extraneous content.

\runin{Implementation Details} We implement an asynchronous service architecture that mirrors the deployed backend. The preprocessing stage includes OCR with automatic fallback, rule-based component aggregation, heading-level generation, stack-based tree construction, and bottom-up metadata integration. The QA stage uses query parsing, location retrieval or semantic+vector joint retrieval, answer verification, and whole-page fallback when verification fails.

\runin{Baselines} We compare \modora against nine state-of-the-art baselines: UDOP~\cite{UDOP}, DocOWL2~\cite{DocOwl2}, M3DocRAG~\cite{M3DocRAG}, SV-RAG~\cite{SV-RAG}, TextRAG~\cite{TextRAG}, QUEST~\cite{QUEST}, ZenDB~\cite{ZenDB}, DocAgent~\cite{DocAgent}, and GPT-5~\cite{GPT-5}.

\subsection{Performance Analysis} 
As illustrated in Figure~\ref{fig:exp1}, \modora achieves an AIC-Acc of 71.1\% on the MMDA benchmark.

\begin{figure}[h] 
\centering 
\includegraphics[width=0.95\linewidth]{Fig/exp_new.pdf} 
\caption{Experimental results on the MMDA dataset.} 
\label{fig:exp1} 
\end{figure}

\runin{Comparative Advantages} \modora outperforms the strongest baseline, DocAgent~\cite{DocAgent} (57.0\%), by a margin of 14.1\%. This improvement stems from the system's ability to transform fragmented OCR elements into layout-aware components, which are then organized into a hierarchical tree.

\runin{Structural and Hybrid Reasoning} While text-centric methods like TextRAG~\cite{TextRAG} (36.2\%) and ZenDB~\cite{ZenDB} (47.1\%) struggle with non-textual elements, \modora's tree-based retrieval accurately aligns semantic cues with visual data. Furthermore, our approach significantly exceeds the performance of end-to-end models such as DocOWL2~\cite{DocOwl2} (29.6\%) and UDOP~\cite{UDOP} (15.8\%), which often fail to capture fine-grained layout distinctions.

\runin{Noise Reduction} Compared to the vanilla GPT-5~\cite{GPT-5} (46.5\%), which processes full document pages, \modora's query-adaptive retrieval mechanism filters irrelevant content more effectively, resulting in higher reasoning precision.

\subsection{Case Study: End-to-End System Capabilities}\label{subsec:case_study}

Rather than focusing only on final QA accuracy, these cases illustrate how the system supports structural correction, cross-modal verification, spatial inspection, and evidence-grounded interaction throughout the end-to-end pipeline.

\runin{Scenario 1: Structural Correction for Section-Level Navigation (C1)} A user uploads a scanned paper and asks: ``What is discussed in the second subsection of Section III?'' Because OCR may fragment headings and body text, a flat chunking pipeline can mix unrelated paragraphs and captions, making section-level navigation unreliable. In \modora, the document is first aggregated into layout-aware components and organized into a CCTree. The user can then inspect the recovered hierarchy in the tree visualizer, identify a misplaced heading node, and manually correct its parent-child relation. After this refinement, \modora retrieves the complete logical branch of Section III and grounds the returned answer in the corresponding PDF regions. This case shows that \modora supports editable structural analysis rather than only final-answer generation.

\runin{Scenario 2: Cross-Modal Verification for Table-Text Reasoning (C2)} A user inspects an experimental report and asks: ``Which parameter setting corresponds to the `winter' experiment in the table, and how is it described in the text?'' The evidence is split across table cells and narrative paragraphs, so the user needs not only an answer but also a way to verify where it comes from. \modora first applies VLM-based enrichment to convert the table into semantic triplets that preserve row-column relations, and then coordinates semantic and vector retrieval to locate both the relevant table entry and the explanatory text span. In the grounding view, the system highlights the exact table cells together with the supporting sentence in the PDF. The user can therefore verify whether the numeric configuration and the textual interpretation are consistent. This case demonstrates \modora's role as a cross-modal evidence alignment and verification system, not merely a QA model.

\runin{Scenario 3: Spatial Inspection for Visual Element Identification (C3)} A user examines a visually dense page and asks: ``What is the logo in the top-right corner?'' Such questions depend primarily on spatial cues rather than pure textual similarity. In this case, \modora activates its location retrieval path to map the query onto a normalized page grid and select overlapping visual components. If the initially retrieved node does not provide sufficient evidence, the verification module suppresses unsupported answers and triggers fallback reasoning over a broader region. The final response is returned together with grounded highlights on the PDF, allowing the user to directly inspect the referenced visual element. This illustrates how \modora supports reliable spatial inspection in real document analysis workflows.
